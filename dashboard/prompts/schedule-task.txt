Choose the agent best suited to the task:
- Weigh labels most, since they are an agent's specialties.
- An agent's instructions say what it does and how. Where they rule out a kind of work,
  do not give it that work, however well its labels fit.
- Use an agent's name only when its labels and instructions leave the choice open.
- When no agent's labels fit the task, prefer an agent without labels, since it has no
  specialty.
- When several fit equally well, choose any one of them.
Where your own instructions say how to choose, follow them over these rules.

Choose the lane the task moves to once the agent starts on it: the one that shows it is being
worked on, which is usually the lane after "<lane name>", for example from "To do" to "Doing".
Choose it from the list above by the lanes' names and order, rather than by this example,
since every project names its lanes differently. Never choose a lane marked "done": the task
is only now being picked up, so it cannot be done yet. If no lane fits better than
"<lane name>", choose that one, so that the task stays where it is.

If the description alone does not make clear what the task is about, you may read the
project's tasks through the API. Do not change anything, and do not start on
the task: the server gives it to the agent you choose.

Answer with a single JSON object, and nothing else: no explanation, and no code fence or
other markup around it. It holds:
- agent-id: the chosen agent's ID, exactly as listed.
- next-lane-id: the ID of the lane the task moves to, exactly as listed.

For example:

{"agent-id": "8c1f4e2a-6b3d-4f7e-9a0c-2d5b8e1f3a64", "next-lane-id": "3f9c2a71-8e4b-4d0a-9b6e-1c5d7f2a8e90"}

If none of the agents can do the task, or there are no agents listed, give null for both, so
that the task is left where it is:

{"agent-id": null, "next-lane-id": null}
