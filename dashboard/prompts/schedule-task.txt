First decide what the task's next step is, from its lane, its notes and the lanes of the board:
- A new task needs its work done. Its next lane is the one that shows it is being worked on,
  usually the lane after "<lane name>", for example from "To do" to "Doing".
- A task whose latest note is the result of finished work goes on to the lane that comes next
  for such work, for example from "Doing" to "To review", where another agent checks it. When
  the next lane is a done one, or the board has no lane for a further step, the task is
  finished: close it.
- A task whose latest result asks for changes, for example a review that found problems,
  goes back to the lane where that work is done, for example from "To review" to "Doing".
- A task whose latest result says it was split up into other tasks is finished: close it.
- A task whose latest result says the work could not be done, or that something is missing,
  is left where it is, unless another agent is clearly better suited and has not tried it yet.
- A task whose notes show it going round the same lanes without getting any further, for
  example the same changes asked for over and over, is left where it is, for a person to look at.
Choose lanes from the list above by their names and order, rather than by these examples,
since every project names its lanes differently.

Then, unless the task is closed or left where it is, choose the agent best suited to the
next step:
- Weigh labels most, since they are an agent's specialties.
- An agent's instructions say what it does and how. Where they rule out a kind of work,
  do not give it that work, however well its labels fit.
- Use an agent's name only when its labels and instructions leave the choice open.
- When no agent's labels fit the step, prefer an agent without labels, since it has no
  specialty.
- When several fit equally well, choose any one of them.
Where your own instructions say how to choose, follow them over these rules.

If the description and notes alone do not make clear what the task is about, you may read the
project's tasks through the API. Do not change anything, and do not start on the task: the
server moves it and gives it to the agent you choose.

Answer with a single JSON object, and nothing else: no explanation, and no code fence or
other markup around it. It holds:
- agent-id: the chosen agent's ID, exactly as listed, or null when no agent is to work on it.
- next-lane-id: the ID of the lane the task moves to, exactly as listed, or null when it stays
  where it is.

To give the task to an agent, name the agent and a lane that is not marked "done". The lane
may be "<lane name>" itself, when that is where the next step is done:

{"agent-id": "8c1f4e2a-6b3d-4f7e-9a0c-2d5b8e1f3a64", "next-lane-id": "3f9c2a71-8e4b-4d0a-9b6e-1c5d7f2a8e90"}

To close the task, give null for the agent and a lane marked "done", the one nearest the end
of the board when there are several:

{"agent-id": null, "next-lane-id": "5d2e8b40-1a7c-4f39-8e6d-0b9c3a4f7e21"}

To leave the task where it is, for a person to look at, such as when none of the agents can do
the next step, or there are no agents listed, give null for both:

{"agent-id": null, "next-lane-id": null}
